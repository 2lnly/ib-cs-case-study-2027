Neural network that learns efficient data encoding in an unsupervised manner

[TABLE]

An **autoencoder** is a type of [artificial neural network](https://en.wikipedia.org/wiki/Artificial_neural_network "Artificial neural network") used to learn [efficient codings](https://en.wikipedia.org/wiki/Feature_learning "Feature learning") of unlabeled data ([unsupervised learning](https://en.wikipedia.org/wiki/Unsupervised_learning "Unsupervised learning")). An autoencoder learns two functions: an encoding function that transforms the input data, and a decoding function that recreates the input data from the encoded representation. The autoencoder learns an efficient representation (encoding) for a set of data, typically for [dimensionality reduction](https://en.wikipedia.org/wiki/Dimensionality_reduction "Dimensionality reduction"), to generate lower-dimensional embeddings for subsequent use by other [machine learning](https://en.wikipedia.org/wiki/Machine_learning "Machine learning") algorithms.^([\[1\]](#cite_note-1))

Variants exist which aim to make the learned representations assume useful properties.^([\[2\]](#cite_note-:0-2)) Examples are regularized autoencoders (*sparse*, *denoising* and *contractive* autoencoders), which are effective in learning representations for subsequent [classification](https://en.wikipedia.org/wiki/Statistical_classification "Statistical classification") tasks,^([\[3\]](#cite_note-:4-3)) and [*variational* autoencoders](https://en.wikipedia.org/wiki/Variational_autoencoder "Variational autoencoder"), which can be used as [generative models](https://en.wikipedia.org/wiki/Generative_model "Generative model").^([\[4\]](#cite_note-:11-4)) Autoencoders are applied to many problems, including [facial recognition](https://en.wikipedia.org/wiki/Facial_recognition_system "Facial recognition system"),^([\[5\]](#cite_note-5)) [feature detection](https://en.wikipedia.org/wiki/Feature_(computer_vision) "Feature (computer vision)"),^([\[6\]](#cite_note-:2-6)) [anomaly detection](https://en.wikipedia.org/wiki/Anomaly_detection "Anomaly detection"), and [learning the meaning of words](https://en.wikipedia.org/wiki/Word_embedding "Word embedding").^([\[7\]](#cite_note-7)[\[8\]](#cite_note-8)) In terms of [data synthesis](https://en.wikipedia.org/wiki/Synthetic_data "Synthetic data"), autoencoders can also be used to randomly generate new data that is similar to the input (training) data.^([\[6\]](#cite_note-:2-6))

## Mathematical principles

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=1 "Edit section: Mathematical principles")\]

### Definition

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=2 "Edit section: Definition")\]

An autoencoder is defined by the following components:

> Two sets: the space of encoded messages $\mathcal{Z}$; the space of decoded messages $\mathcal{X}$. Typically $\mathcal{X}$ and $\mathcal{Z}$ are [Euclidean spaces](https://en.wikipedia.org/wiki/Euclidean_space "Euclidean space"), that is, $\mathcal{X} = {\mathbb{R}}^{m},\mathcal{Z} = {\mathbb{R}}^{n}$ with $m > n.$

> Two [parametrized](https://en.wikipedia.org/wiki/Parametrization_(geometry) "Parametrization (geometry)") families of functions: the encoder family $E_{\phi}:\mathcal{X}\rightarrow\mathcal{Z}$, parametrized by $\phi$; the decoder family $D_{\theta}:\mathcal{Z}\rightarrow\mathcal{X}$, parametrized by $\theta$.

For any $x \in \mathcal{X}$, we usually write $z = E_{\phi}(x)$, and refer to it as the code, the [latent variable](https://en.wikipedia.org/wiki/Latent_variable "Latent variable"), latent representation, latent vector, etc. Conversely, for any $z \in \mathcal{Z}$, we usually write $x^{\prime} = D_{\theta}(z)$, and refer to it as the (decoded) message.

Usually, both the encoder and the decoder are defined as [multilayer perceptrons](https://en.wikipedia.org/wiki/Multilayer_perceptron "Multilayer perceptron") (MLPs). For example, a one-layer-MLP encoder $E_{\phi}$ is:

$E_{\phi}(\mathbf{x}) = \sigma(Wx + b)$

where $\sigma$ is an element-wise [activation function](https://en.wikipedia.org/wiki/Activation_function "Activation function"), $W$ is a "weight" matrix, and $b$ is a "bias" vector.

### Training an autoencoder

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=3 "Edit section: Training an autoencoder")\]

An autoencoder, by itself, is simply a tuple of two functions. To judge its *quality*, we need a *task*. A task is defined by a reference probability distribution $\mu_{ref}$ over $\mathcal{X}$, and a "reconstruction quality" function $d:\mathcal{X} \times \mathcal{X}\rightarrow\lbrack 0,\infty\rbrack$, such that $d(x,x^{\prime})$ measures how much $x^{\prime}$ differs from $x$.

With those, we can define the loss function for the autoencoder as$$L(\theta,\phi):={\mathbb{E}}_{x \sim \mu_{ref}}\lbrack d(x,D_{\theta}(E_{\phi}(x)))\rbrack$$The *optimal* autoencoder for the given task $(\mu_{ref},d)$ is then $\arg\min\limits_{\theta,\phi}L(\theta,\phi)$. The search for the optimal autoencoder can be accomplished by any mathematical optimization technique, but usually by [gradient descent](https://en.wikipedia.org/wiki/Gradient_descent "Gradient descent"). This search process is referred to as "training the autoencoder".

In most situations, the reference distribution is just the [empirical distribution](https://en.wikipedia.org/wiki/Empirical_measure "Empirical measure") given by a dataset $\{ x_{1},{...},x_{N}\} \subset \mathcal{X}$, so that$$\mu_{ref} = \frac{1}{N}\sum\limits_{i = 1}^{N}\delta_{x_{i}}$$

where $\delta_{x_{i}}$ is the [Dirac measure](https://en.wikipedia.org/wiki/Dirac_measure "Dirac measure"), the quality function is just $L^{2}$ loss: $d(x,x^{\prime}) = \| x - x^{\prime}\|_{2}^{2}$, and $\| \cdot \|_{2}$ is the [Euclidean norm](https://en.wikipedia.org/wiki/Norm_(mathematics)#Euclidean_norm "Norm (mathematics)"). Then the problem of searching for the optimal autoencoder is just a [least-squares](https://en.wikipedia.org/wiki/Least_squares "Least squares") optimization:$$\min\limits_{\theta,\phi}L(\theta,\phi),\qquad\text{where~}L(\theta,\phi) = \frac{1}{N}\sum\limits_{i = 1}^{N}\| x_{i} - D_{\theta}(E_{\phi}(x_{i}))\|_{2}^{2}$$

### Interpretation

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=4 "Edit section: Interpretation")\]

An autoencoder has two main parts: an encoder that maps the message to a code, and a decoder that reconstructs the message from the code. An optimal autoencoder would perform as close to perfect reconstruction as possible, with "close to perfect" defined by the reconstruction quality function $d$.

The simplest way to perform the copying task perfectly would be to duplicate the signal. To suppress this behavior, the code space $\mathcal{Z}$ usually has fewer dimensions than the message space $\mathcal{X}$.

Such an autoencoder is called *undercomplete*. It can be interpreted as [compressing](https://en.wikipedia.org/wiki/Data_compression "Data compression") the message, or [reducing its dimensionality](https://en.wikipedia.org/wiki/Dimensionality_reduction "Dimensionality reduction").^([\[9\]](#cite_note-:12-9)[\[10\]](#cite_note-:7-10))

At the limit of an ideal undercomplete autoencoder, every possible code $z$ in the code space is used to encode a message $x$ that really appears in the distribution $\mu_{ref}$, and the decoder is also perfect: $D_{\theta}(E_{\phi}(x)) = x$. This ideal autoencoder can then be used to generate messages indistinguishable from real messages, by feeding its decoder arbitrary code $z$ and obtaining $D_{\theta}(z)$, which is a message that really appears in the distribution $\mu_{ref}$.

If the code space $\mathcal{Z}$ has dimension larger than (*overcomplete*), or equal to, the message space $\mathcal{X}$, or the hidden units are given enough capacity, an autoencoder can learn the [identity function](https://en.wikipedia.org/wiki/Identity_function "Identity function") and become useless. However, experimental results found that overcomplete autoencoders might still [learn useful features](https://en.wikipedia.org/wiki/Feature_learning "Feature learning").^([\[11\]](#cite_note-bengio-11))

In the ideal setting, the code dimension and the model capacity could be set on the basis of the complexity of the data distribution to be modeled. A standard way to do so is to add modifications to the basic autoencoder, to be detailed below.^([\[2\]](#cite_note-:0-2))

## Variations

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=5 "Edit section: Variations")\]

### Variational autoencoder (VAE)

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=6 "Edit section: Variational autoencoder (VAE)")\]

[![](//thumb.wikimedia.org/wikipedia/commons/thumb/4/4a/VAE_Basic.png/330px-VAE_Basic.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:VAE_Basic.png)

The basic scheme of a variational autoencoder. The model receives $x$ as input. The encoder compresses it into the latent space. The decoder receives as input the information sampled from the latent space and produces $x^{\prime}$ as similar as possible to $x$.

Main article: [Variational autoencoder](https://en.wikipedia.org/wiki/Variational_autoencoder "Variational autoencoder")

[Variational autoencoders](https://en.wikipedia.org/wiki/Variational_autoencoder "Variational autoencoder") (VAEs) belong to the families of [variational Bayesian methods](https://en.wikipedia.org/wiki/Variational_Bayesian_methods "Variational Bayesian methods"). Despite the architectural similarities with basic autoencoders, VAEs are architected with different goals and have a different mathematical formulation. The latent space is, in this case, composed of a mixture of distributions instead of fixed vectors.

Given an input dataset $x$ characterized by an unknown probability function $P(x)$ and a multivariate latent encoding vector $z$, the objective is to model the data as a distribution $p_{\theta}(x)$, with $\theta$ defined as the set of the network parameters so that $p_{\theta}(x) = \int_{z}p_{\theta}(x,z)dz$.

### Sparse autoencoder (SAE)

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=7 "Edit section: Sparse autoencoder (SAE)")\]

Inspired by the [sparse coding](https://en.wikipedia.org/wiki/Sparse_coding "Sparse coding") hypothesis in neuroscience, *sparse autoencoders* (SAE) are variants of autoencoders, such that the codes $E_{\phi}(x)$ for messages tend to be *sparse codes*, that is, $E_{\phi}(x)$ is close to zero in most entries. Sparse autoencoders may include more (rather than fewer) hidden units than inputs, but only a small number of the hidden units are allowed to be active at the same time.^([\[12\]](#cite_note-domingos-12)) Encouraging sparsity improves performance on classification tasks.^([\[13\]](#cite_note-:1-13))

[![](//thumb.wikimedia.org/wikipedia/commons/thumb/8/83/Autoencoder_sparso.png/250px-Autoencoder_sparso.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Autoencoder_sparso.png)

Simple schema of a single-layer sparse autoencoder. The hidden nodes in bright yellow are activated, while the light yellow ones are inactive. The activation depends on the input.

There are two main ways to enforce sparsity. One way is to simply clamp all but the highest-k activations of the latent code to zero. This is the **k-sparse autoencoder**.^([\[13\]](#cite_note-:1-13))

The k-sparse autoencoder inserts the following "k-sparse function" in the latent layer of a standard autoencoder:$$f_{k}(x_{1},{...},x_{n}) = (x_{1}b_{1},{...},x_{n}b_{n})$$where $b_{i} = 1$ if $|x_{i}|$ ranks in the top k, and 0 otherwise.

Backpropagating through $f_{k}$ is simple: set gradient to 0 for $b_{i} = 0$ entries, and keep gradient for $b_{i} = 1$ entries. This is essentially a generalized [ReLU](https://en.wikipedia.org/wiki/Rectifier_(neural_networks) "Rectifier (neural networks)") function.^([\[13\]](#cite_note-:1-13))

The other way is a [relaxed version](https://en.wikipedia.org/wiki/Relaxation_(approximation) "Relaxation (approximation)") of the k-sparse autoencoder. Instead of forcing sparsity, we add a **sparsity regularization loss**, then optimize for$$\min\limits_{\theta,\phi}L(\theta,\phi) + \lambda L_{\text{sparse}}(\theta,\phi)$$where $\lambda > 0$ measures how much sparsity we want to enforce.^([\[14\]](#cite_note-:6-14))

Let the autoencoder architecture have $K$ layers. To define a sparsity regularization loss, we need a "desired" sparsity ${\widehat{\rho}}_{k}$ for each layer, a weight $w_{k}$ for how much to enforce each sparsity, and a function $s:\lbrack 0,1\rbrack \times \lbrack 0,1\rbrack\rightarrow\lbrack 0,\infty\rbrack$ to measure how much two sparsities differ.

For each input $x$, let the actual sparsity of activation in each layer $k$ be$$\rho_{k}(x) = \frac{1}{n}\sum\limits_{i = 1}^{n}a_{k,i}(x)$$where $a_{k,i}(x)$ is the activation in the $i$ -th neuron of the $k$ -th layer upon input $x$.

The sparsity loss upon input $x$ for one layer is $s({\widehat{\rho}}_{k},\rho_{k}(x))$, and the sparsity regularization loss for the entire autoencoder is the expected weighted sum of sparsity losses:$$L_{\text{sparse}}(\theta,\phi) = {\mathbb{E}}_{x \sim \mu_{X}}\left\lbrack \sum\limits_{k \in 1:K}w_{k}s({\widehat{\rho}}_{k},\rho_{k}(x)) \right\rbrack$$Typically, the function $s$ is either the [Kullback–Leibler (KL) divergence](https://en.wikipedia.org/wiki/Kullback–Leibler_divergence "Kullback–Leibler divergence"), as^([\[13\]](#cite_note-:1-13)[\[14\]](#cite_note-:6-14)[\[15\]](#cite_note-15)[\[16\]](#cite_note-16))

$s(\rho,\widehat{\rho}) = KL(\rho||\widehat{\rho}) = \rho\log\frac{\rho}{\widehat{\rho}} + (1 - \rho)\log\frac{1 - \rho}{1 - \widehat{\rho}}$

or the L1 loss, as $s(\rho,\widehat{\rho}) = |\rho - \widehat{\rho}|$, or the L2 loss, as $s(\rho,\widehat{\rho}) = |\rho - \widehat{\rho}|^{2}$.

Alternatively, the sparsity regularization loss may be defined without reference to any "desired sparsity", but simply force as much sparsity as possible. In this case, one can define the sparsity regularization loss as $$L_{\text{sparse}}(\theta,\phi) = {\mathbb{E}}_{x \sim \mu_{X}}\left\lbrack \sum\limits_{k \in 1:K}w_{k}\| h_{k}\| \right\rbrack$$where $h_{k}$ is the activation vector in the $k$-th layer of the autoencoder. The norm $\| \cdot \|$ is usually the L1 norm (giving the L1 sparse autoencoder) or the L2 norm (giving the L2 sparse autoencoder).

### Denoising autoencoder (DAE)

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=8 "Edit section: Denoising autoencoder (DAE)")\]

[![](//thumb.wikimedia.org/wikipedia/commons/thumb/1/18/Denoising-autoencoder.png/250px-Denoising-autoencoder.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Denoising-autoencoder.png)

A schema of a denoising autoencoder

*Denoising autoencoders* (DAE) try to achieve a *good* representation by changing the *reconstruction criterion*.^([\[2\]](#cite_note-:0-2)[\[3\]](#cite_note-:4-3))

A DAE, originally called a "robust autoassociative network" by Mark A. Kramer,^([\[17\]](#cite_note-:13-17)) is trained by intentionally corrupting the inputs of a standard autoencoder during training. A noise process is defined by a probability distribution $\mu_{T}$ over functions $T:\mathcal{X}\rightarrow\mathcal{X}$. That is, the function $T$ takes a message $x \in \mathcal{X}$, and corrupts it to a noisy version $T(x)$. The function $T$ is selected randomly, with a probability distribution $\mu_{T}$.

Given a task $(\mu_{\text{ref}},d)$, the problem of training a DAE is the optimization problem:$$\min\limits_{\theta,\phi}L(\theta,\phi) = {\mathbb{E}}_{x \sim \mu_{X},T \sim \mu_{T}}\lbrack d(x,(D_{\theta} \circ E_{\phi} \circ T)(x))\rbrack$$That is, the optimal DAE should take any noisy message and attempt to recover the original message without noise, thus the name "denoising"*.*

Usually, the noise process $T$ is applied only during training and testing, not during downstream use.

The use of DAE depends on two assumptions:

- There exist representations to the messages that are relatively stable and robust to the type of noise we are likely to encounter;
- The said representations capture structures in the input distribution that are useful for our purposes.^([\[3\]](#cite_note-:4-3))

Example noise processes include:

- additive isotropic [Gaussian noise](https://en.wikipedia.org/wiki/Additive_white_Gaussian_noise "Additive white Gaussian noise"),
- masking noise (a fraction of the input is randomly chosen and set to 0)
- [salt-and-pepper noise](https://en.wikipedia.org/wiki/Salt-and-pepper_noise "Salt-and-pepper noise") (a fraction of the input is randomly chosen and randomly set to its minimum or maximum value).^([\[3\]](#cite_note-:4-3))

### Contractive autoencoder (CAE)

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=9 "Edit section: Contractive autoencoder (CAE)")\]

A *contractive autoencoder* (CAE) adds the contractive regularization loss to the standard autoencoder loss:$$\min\limits_{\theta,\phi}L(\theta,\phi) + \lambda L_{\text{cont}}(\theta,\phi)$$where $\lambda > 0$ measures how much contractive-ness we want to enforce. The contractive regularization loss itself is defined as the expected square of [Frobenius norm](https://en.wikipedia.org/wiki/Frobenius_norm "Frobenius norm") of the [Jacobian matrix](https://en.wikipedia.org/wiki/Jacobian_matrix_and_determinant "Jacobian matrix and determinant") of the encoder activations with respect to the input:$$L_{\text{cont}}(\theta,\phi) = {\mathbb{E}}_{x \sim \mu_{ref}}\|\nabla_{x}E_{\phi}(x)\|_{F}^{2}$$To understand what $L_{\text{cont}}$ measures, note the fact$$\| E_{\phi}(x + \delta x) - E_{\phi}(x)\|_{2} \leq \|\nabla_{x}E_{\phi}(x)\|_{F}\|\delta x\|_{2}$$for any message $x \in \mathcal{X}$, and small variation $\delta x$ in it. Thus, if $\|\nabla_{x}E_{\phi}(x)\|_{F}^{2}$ is small, it means that a small neighborhood of the message maps to a small neighborhood of its code. This is a desired property, as it means small variation in the message leads to small, perhaps even zero, variation in its code, like how two pictures may look the same even if they are not exactly the same.

The CAE can be understood as an infinitesimal limit of DAE: in the limit of small Gaussian input noise, DAEs make the reconstruction function resist small but finite-sized input perturbations, while CAEs make the extracted features resist infinitesimal input perturbations. However, while DAEs encourage robustness of reconstruction, CAEs encourage robustness of representation. Additionally, DAEs' robustness is obtained stochastically, by having various corrupted versions of a training point aim for an identical reconstruction. In contrast, CAEs' robustness to small perturbations is obtained analytically by penalizing the Frobenius norm of the encoder Jacobian, $\|\nabla_{x}E_{\phi}(x)\|_{F}^{2}$, evaluated at the training samples.^([\[18\]](#cite_note-18))

### Minimum description length autoencoder (MDL-AE)

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=10 "Edit section: Minimum description length autoencoder (MDL-AE)")\]

A *minimum description length autoencoder* (MDL-AE) is an advanced variation of the traditional autoencoder, which leverages principles from information theory, specifically the [Minimum Description Length (MDL) principle](https://en.wikipedia.org/wiki/Minimum_description_length "Minimum description length"). The MDL principle posits that the best model for a dataset is the one that provides the shortest combined encoding of the model and the data. In the context of [autoencoders](https://en.wikipedia.org/wiki/Autoencoders "Autoencoders"), this principle is applied to ensure that the learned representation is not only compact but also interpretable and efficient for reconstruction.

The MDL-AE seeks to minimize the total description length of the data, which includes the size of the [latent representation](https://en.wikipedia.org/wiki/Latent_representation?action=edit&redlink=1 "Latent representation (page does not exist)") (code length) and the error in reconstructing the original data. The objective can be expressed as $L_{\text{code}} + L_{\text{error}}$, where $L_{\text{code}}$ represents the length of the compressed latent representation and $L_{\text{error}}$ denotes the reconstruction error.^([\[19\]](#cite_note-:5-19))

### Concrete autoencoder (CAE)

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=11 "Edit section: Concrete autoencoder (CAE)")\]

The *concrete autoencoder* is designed for discrete feature selection.^([\[20\]](#cite_note-20)) A concrete autoencoder forces the latent space to consist only of a user-specified number of features. The concrete autoencoder uses a continuous [relaxation](https://en.wikipedia.org/wiki/Relaxation_(approximation) "Relaxation (approximation)") of the [categorical distribution](https://en.wikipedia.org/wiki/Categorical_distribution "Categorical distribution") to allow gradients to pass through the feature selector layer, which makes it possible to use standard [backpropagation](https://en.wikipedia.org/wiki/Backpropagation "Backpropagation") to learn an optimal subset of input features that minimize reconstruction loss.

## Advantages of depth

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=12 "Edit section: Advantages of depth")\]

[![](//thumb.wikimedia.org/wikipedia/commons/thumb/2/28/Autoencoder_structure.png/500px-Autoencoder_structure.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Autoencoder_structure.png)

Schematic structure of an autoencoder with 3 fully connected hidden layers. The code (z, or h for reference in the text) is the most internal layer.

Autoencoders are often trained with a single-layer encoder and a single-layer decoder, but using many-layered (deep) encoders and decoders offers many advantages.^([\[2\]](#cite_note-:0-2))

- Depth can exponentially reduce the computational cost of representing some functions.
- Depth can exponentially decrease the amount of training data needed to learn some functions.
- Experimentally, deep autoencoders yield better compression compared to shallow or linear autoencoders.^([\[10\]](#cite_note-:7-10))
- Depth allows for advantages over traditional methods as one can show that after training single layer linear autoencoders have a latent space whose vectors span the same subspace as the eigenvectors found in [Principal component analysis](https://en.wikipedia.org/wiki/Principal_component_analysis "Principal component analysis").^([\[21\]](#cite_note-21))

### Training

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=13 "Edit section: Training")\]

[Geoffrey Hinton](https://en.wikipedia.org/wiki/Geoffrey_Hinton "Geoffrey Hinton") developed the [deep belief network](https://en.wikipedia.org/wiki/Deep_belief_network "Deep belief network") technique for training many-layered deep autoencoders. His method involves treating each neighboring set of two layers as a [restricted Boltzmann machine](https://en.wikipedia.org/wiki/Restricted_Boltzmann_machine "Restricted Boltzmann machine") so that pretraining approximates a good solution, then using backpropagation to fine-tune the results.^([\[10\]](#cite_note-:7-10))

Researchers have debated whether joint training (i.e. training the whole architecture together with a single global reconstruction objective to optimize) would be better for deep auto-encoders.^([\[22\]](#cite_note-:9-22)) A 2015 study showed that joint training learns better data models along with more representative features for classification as compared to the layerwise method.^([\[22\]](#cite_note-:9-22)) However, their experiments showed that the success of joint training depends heavily on the regularization strategies adopted.^([\[22\]](#cite_note-:9-22)[\[23\]](#cite_note-23))

## History

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=14 "Edit section: History")\]

(Oja, 1982)^([\[24\]](#cite_note-24)) noted that [PCA](https://en.wikipedia.org/wiki/Principal_component_analysis "Principal component analysis") is equivalent to a neural network with one hidden layer with identity activation function. In the language of autoencoding, the input-to-hidden module is the encoder, and the hidden-to-output module is the decoder. Subsequently, in (Baldi and Hornik, 1989)^([\[25\]](#cite_note-auto-25)) and (Kramer, 1991)^([\[9\]](#cite_note-:12-9)) generalized PCA to autoencoders, a technique which they termed "nonlinear PCA".

Immediately after the resurgence of neural networks in the 1980s, it was suggested in 1986^([\[26\]](#cite_note-26)) that a neural network be put in "auto-association mode". This was then implemented in (Harrison, 1987)^([\[27\]](#cite_note-27)) and (Elman, Zipser, 1988)^([\[28\]](#cite_note-28)) for speech and in (Cottrell, Munro, Zipser, 1987)^([\[29\]](#cite_note-29)) for images.^([\[30\]](#cite_note-:14-30)) In (Hinton, Salakhutdinov 2006),^([\[31\]](#cite_note-:72-31)) [deep belief networks](https://en.wikipedia.org/wiki/Deep_belief_network "Deep belief network") were developed. These train a pair [restricted Boltzmann machines](https://en.wikipedia.org/wiki/Restricted_Boltzmann_machine "Restricted Boltzmann machine") as encoder-decoder pairs, then train another pair on the latent representation of the first pair, and so on.^([\[32\]](#cite_note-scholar-32))

The first applications of AE date to early 1990s.^([\[2\]](#cite_note-:0-2)[\[33\]](#cite_note-33)[\[19\]](#cite_note-:5-19)) Their most traditional application was [dimensionality reduction](https://en.wikipedia.org/wiki/Dimensionality_reduction "Dimensionality reduction") or [feature learning](https://en.wikipedia.org/wiki/Feature_learning "Feature learning"), but the concept became widely used for learning [generative models](https://en.wikipedia.org/wiki/Generative_model "Generative model") of data.^([\[34\]](#cite_note-VAE-34)[\[35\]](#cite_note-gan_faces-35)) Some of the most powerful [AIs](https://en.wikipedia.org/wiki/Artificial_intelligence "Artificial intelligence") in the 2010s involved autoencoder modules as a component of larger AI systems, such as VAE in [Stable Diffusion](https://en.wikipedia.org/wiki/Stable_Diffusion "Stable Diffusion"), discrete VAE in Transformer-based image generators like [DALL-E 1](https://en.wikipedia.org/wiki/DALL-E "DALL-E"), etc.

During the early days, when the terminology was uncertain, the autoencoder has also been called identity mapping,^([\[25\]](#cite_note-auto-25)[\[9\]](#cite_note-:12-9)) auto-associating,^([\[36\]](#cite_note-36)) [self-supervised](https://en.wikipedia.org/wiki/Self-supervised_learning "Self-supervised learning") [backpropagation](https://en.wikipedia.org/wiki/Backpropagation "Backpropagation"),^([\[9\]](#cite_note-:12-9)) or Diabolo network.^([\[37\]](#cite_note-37)[\[11\]](#cite_note-bengio-11))

## Applications

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=15 "Edit section: Applications")\]

The two main applications of autoencoders are [dimensionality reduction](https://en.wikipedia.org/wiki/Dimensionality_reduction "Dimensionality reduction") and [information retrieval](https://en.wikipedia.org/wiki/Information_retrieval "Information retrieval") (or [associative memory](https://en.wikipedia.org/wiki/Content-addressable_memory "Content-addressable memory")),^([\[2\]](#cite_note-:0-2)) but modern variations have been applied to other tasks.

### Dimensionality reduction

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=16 "Edit section: Dimensionality reduction")\]

[![](//thumb.wikimedia.org/wikipedia/commons/thumb/0/0b/PCA_vs_Linear_Autoencoder.png/250px-PCA_vs_Linear_Autoencoder.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:PCA_vs_Linear_Autoencoder.png)

Plot of the first two Principal Components (left) and a two-dimension hidden layer of a Linear Autoencoder (Right) applied to the [Fashion MNIST](https://en.wikipedia.org/wiki/Fashion_MNIST "Fashion MNIST") dataset.^([\[38\]](#cite_note-:10-38)) The two models being both linear learn to span the same subspace. The projection of the data points is indeed identical, apart from rotation of the subspace. While PCA selects a specific orientation up to reflections in the general case, the cost function of a simple autoencoder is invariant to rotations of the latent space.

[Dimensionality reduction](https://en.wikipedia.org/wiki/Dimensionality_reduction "Dimensionality reduction") was one of the first [deep learning](https://en.wikipedia.org/wiki/Deep_learning "Deep learning") applications.^([\[2\]](#cite_note-:0-2))

For Hinton's 2006 study,^([\[10\]](#cite_note-:7-10)) he pretrained a multi-layer autoencoder with a stack of [RBMs](https://en.wikipedia.org/wiki/Restricted_Boltzmann_machine "Restricted Boltzmann machine") and then used their weights to initialize a deep autoencoder with gradually smaller hidden layers until hitting a bottleneck of 30 neurons. The resulting 30 dimensions of the code yielded a smaller reconstruction error compared to the first 30 components of a principal component analysis (PCA), and learned a representation that was qualitatively easier to interpret, clearly separating data clusters.^([\[2\]](#cite_note-:0-2)[\[10\]](#cite_note-:7-10))

Reducing dimensions can improve performance on tasks such as classification.^([\[2\]](#cite_note-:0-2)) Indeed, the hallmark of dimensionality reduction is to place semantically related examples near each other.^([\[39\]](#cite_note-:3-39))

#### Principal component analysis

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=17 "Edit section: Principal component analysis")\]

[![](//thumb.wikimedia.org/wikipedia/commons/thumb/e/ea/Reconstruction_autoencoders_vs_PCA.png/250px-Reconstruction_autoencoders_vs_PCA.png?utm_source=en.wikipedia.org&utm_campaign=parser&utm_content=thumbnail)](https://en.wikipedia.org/wiki/File:Reconstruction_autoencoders_vs_PCA.png)

Reconstruction of 28x28pixel images by an Autoencoder with a code size of two (two-units hidden layer) and the reconstruction from the first two Principal Components of PCA. Images come from the [Fashion MNIST dataset](https://en.wikipedia.org/wiki/Fashion_MNIST "Fashion MNIST").^([\[38\]](#cite_note-:10-38))

If linear activations are used, or only a single sigmoid hidden layer, then the optimal solution to an autoencoder is strongly related to [principal component analysis](https://en.wikipedia.org/wiki/Principal_component_analysis "Principal component analysis") (PCA).^([\[30\]](#cite_note-:14-30)[\[40\]](#cite_note-40)) The weights of an autoencoder with a single hidden layer of size $p$ (where $p$ is less than the size of the input) span the same vector subspace as the one spanned by the first $p$ principal components, and the output of the autoencoder is an orthogonal projection onto this subspace. The autoencoder weights are not equal to the principal components, and are generally not orthogonal, yet the principal components may be recovered from them using the [singular value decomposition](https://en.wikipedia.org/wiki/Singular_value_decomposition "Singular value decomposition").^([\[41\]](#cite_note-41))

However, the potential of autoencoders resides in their non-linearity, allowing the model to learn more powerful generalizations compared to PCA, and to reconstruct the input with significantly lower information loss.^([\[10\]](#cite_note-:7-10))

### Information retrieval

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=18 "Edit section: Information retrieval")\]

[Information retrieval](https://en.wikipedia.org/wiki/Information_retrieval "Information retrieval") benefits particularly from [dimensionality reduction](https://en.wikipedia.org/wiki/Dimensionality_reduction "Dimensionality reduction") in that search can become more efficient in certain kinds of low dimensional spaces. Autoencoders were indeed applied to semantic hashing, proposed by [Salakhutdinov](https://en.wikipedia.org/wiki/Russ_Salakhutdinov "Russ Salakhutdinov") and Hinton in 2007.^([\[39\]](#cite_note-:3-39)) By training the algorithm to produce a low-dimensional binary code, all database entries could be stored in a [hash table](https://en.wikipedia.org/wiki/Hash_table "Hash table") mapping binary code vectors to entries. This table would then support information retrieval by returning all entries with the same binary code as the query, or slightly less similar entries by flipping some bits from the query encoding.

### Anomaly detection

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=19 "Edit section: Anomaly detection")\]

Another application for autoencoders is [anomaly detection](https://en.wikipedia.org/wiki/Anomaly_detection "Anomaly detection").^([\[17\]](#cite_note-:13-17)[\[42\]](#cite_note-42)[\[43\]](#cite_note-43)[\[44\]](#cite_note-:8-44)[\[45\]](#cite_note-45)[\[46\]](#cite_note-46)) By learning to replicate the most salient features in the training data under some of the constraints described previously, the model is encouraged to learn to precisely reproduce the most frequently observed characteristics. When facing anomalies, the model should worsen its reconstruction performance. In most cases, only data with normal instances are used to train the autoencoder; in others, the frequency of anomalies is small compared to the observation set so that its contribution to the learned representation could be ignored. After training, the autoencoder will accurately reconstruct "normal" data, while failing to do so with unfamiliar anomalous data.^([\[44\]](#cite_note-:8-44)) Reconstruction error (the error between the original data and its low dimensional reconstruction) is used as an anomaly score to detect anomalies.^([\[44\]](#cite_note-:8-44)) Typically, this means that on a validation set the empirical distribution of reconstruction errors is recorded and then (e.g.) the empirical 95-percentile $x_{p}$ is taken as threshold $t:=x_{p}$ to flag anomalous data points: $\left. \text{loss}(x,\text{reconstruction}(x)) > t\;\Longrightarrow\;\text{anomaly} \right.$. Since the threshold is an empirical [quantile](https://en.wikipedia.org/wiki/Quantile "Quantile") estimate, there is an inherent difficulty with "correctly" setting this threshold: In many cases the distribution of the empirical quantile is asymptotically a normal distribution $\text{empirical p-quantile} \sim \mathcal{N}\left( \mu = p,\sigma^{2} = \frac{p(1 - p)}{nf(x_{p})^{2}} \right),$ with $f(x_{p})$ the probability density at the quantile. This means that the variance grows if an extreme quantile is considered (because $f(x_{p})$ is small there). This means that there is a, potentially, a big uncertainty in what is the right choice for the threshold since it is *estimated* from a validation set.

Recent literature has however shown that certain autoencoding models can, counterintuitively, be very good at reconstructing anomalous examples and consequently not able to reliably perform anomaly detection.^([\[47\]](#cite_note-47)[\[48\]](#cite_note-48)) Intuitively, this can be understood by considering those one layer auto encoders which are related to PCA - also in this case there can be perfect rein reconstructions for points which are far away from the data region but which lie on a principal component axis.

It is best to analyze if the anomalies which are flagged by the auto encoder are true anomalies. In this sense all the metrics in [Evaluation of binary classifiers](https://en.wikipedia.org/wiki/Evaluation_of_binary_classifiers "Evaluation of binary classifiers") can be considered. The fundamental challenge which comes with the unsupervised (self-supervised) learning setting is, that labels for rare events do not exist (in which case the labels first have to be gathered and the data set will be imbalanced) or anomaly indicating labels are very rare, introducing larger [confidence intervals](https://en.wikipedia.org/wiki/Confidence_interval "Confidence interval") for these performance estimates.

### Image processing

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=20 "Edit section: Image processing")\]

The characteristics of autoencoders are useful in image processing.

One example can be found in lossy [image compression](https://en.wikipedia.org/wiki/Image_compression "Image compression"), where autoencoders outperformed other approaches and proved competitive against [JPEG 2000](https://en.wikipedia.org/wiki/JPEG_2000 "JPEG 2000").^([\[49\]](#cite_note-49)[\[50\]](#cite_note-50))

Another useful application of autoencoders in image preprocessing is [image denoising](https://en.wikipedia.org/wiki/Image_denoising "Image denoising").^([\[51\]](#cite_note-51)[\[52\]](#cite_note-52)[\[53\]](#cite_note-53))

Autoencoders found use in more demanding contexts such as [medical imaging](https://en.wikipedia.org/wiki/Medical_imaging "Medical imaging") where they have been used for [image denoising](https://en.wikipedia.org/wiki/Image_denoising "Image denoising")^([\[54\]](#cite_note-54)) as well as [super-resolution](https://en.wikipedia.org/wiki/Super-resolution "Super-resolution").^([\[55\]](#cite_note-55)[\[56\]](#cite_note-56)) In image-assisted diagnosis, experiments have applied autoencoders for [breast cancer](https://en.wikipedia.org/wiki/Breast_cancer "Breast cancer") detection^([\[57\]](#cite_note-57)) and for modelling the relation between the cognitive decline of [Alzheimer's disease](https://en.wikipedia.org/wiki/Alzheimer's_disease "Alzheimer's disease") and the latent features of an autoencoder trained with [MRI](https://en.wikipedia.org/wiki/MRI "MRI").^([\[58\]](#cite_note-58))

### Drug discovery

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=21 "Edit section: Drug discovery")\]

In 2019 molecules generated with variational autoencoders were validated experimentally in mice.^([\[59\]](#cite_note-59)[\[60\]](#cite_note-60))

### Popularity prediction

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=22 "Edit section: Popularity prediction")\]

Recently, a stacked autoencoder framework produced promising results in predicting popularity of social media posts,^([\[61\]](#cite_note-61)) which is helpful for online advertising strategies.

### Machine translation

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=23 "Edit section: Machine translation")\]

Autoencoders have been applied to [machine translation](https://en.wikipedia.org/wiki/Machine_translation "Machine translation"), which is usually referred to as [neural machine translation](https://en.wikipedia.org/wiki/Neural_machine_translation "Neural machine translation") (NMT).^([\[62\]](#cite_note-62)[\[63\]](#cite_note-63)) Unlike traditional autoencoders, the output does not match the input - it is in another language. In NMT, texts are treated as sequences to be encoded into the learning procedure, while on the decoder side sequences in the target language(s) are generated. [Language](https://en.wikipedia.org/wiki/Language "Language")-specific autoencoders incorporate further [linguistic](https://en.wikipedia.org/wiki/Linguistic "Linguistic") features into the learning procedure, such as Chinese decomposition features.^([\[64\]](#cite_note-64)) Machine translation is rarely still done with autoencoders, due to the availability of more effective [transformer](https://en.wikipedia.org/wiki/Transformer_(machine_learning_model) "Transformer (machine learning model)") networks.

### Communication Systems

\[[edit](/w/index.php?title=Autoencoder&action=edit&section=24 "Edit section: Communication Systems")\]

Autoencoders in communication systems are important because they help in encoding data into a more resilient representation for channel impairments, which is crucial for transmitting information while minimizing errors. In Addition, AE-based systems can optimize end-to-end communication performance. This approach can solve the several limitations of designing communication systems such as the inherent difficulty in accurately modeling the complex behavior of real-world channels.^([\[65\]](#cite_note-65))
